Quick Start

Two lines to integrate

Change base_url to point at the middleware. Everything else — your API key, model name, message format — stays exactly the same.

from openai import OpenAI

# Before: direct to OpenAI
# client = OpenAI(api_key="sk-...")

# After: route through middleware (one line change)
client = OpenAI(
    api_key="sk-...",
    base_url="http://localhost:8000/v1", # ← only change
)

# Everything else is identical
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Explain RLHF."}],
)

# Middleware telemetry in every response
meta = response._middleware
print(f"Saved {meta['pct_saved']}% — ${meta['cost_usd_saved']:.5f} this request")

Architecture

Five-stage compression pipeline

Every request passes through all five stages before reaching the LLM. The user message is never modified. Only history is compressed.

1
Tokenizer baseline lossless
Counts tokens using tiktoken (OpenAI) or character heuristic (Anthropic). Establishes the "before" measurement that drives all savings metrics.
2
Structural compressor lossless
JSON minification, verbose key shortening (authorization_token → auth_tok), whitespace normalization, redundant punctuation removal. Zero semantic loss. Confidence always 1.0.
3
Semantic deduplicator lossless lossy
Embeds each history turn and collapses near-duplicate turns (cosine similarity ≥ threshold). Uses sentence-transformers when installed, TF-IDF fallback otherwise. Measured savings: up to 47% on repetitive sessions.
4
Relevance scorer lossy
Scores each history turn against the current query. Prunes low-signal turns. Entity-graph protected turns are immune to pruning regardless of score — files, functions, task IDs are never dropped.
5
Rolling summarizer lossy
Fires when history exceeds the token budget after stages 2–4. Compresses old turns into a keyword summary. Entity facts are always pinned into the summary — the model never loses load-bearing context.

⬡ Entity Graph — the feature no competitor has

Every other compression proxy treats your conversation as a flat list of text to shrink. We model it as a graph — tracking the files, functions, task IDs, URLs, and people mentioned across turns. When the relevance pruner wants to drop a turn, it first checks whether that turn introduced an entity the current query references. If it did, the turn is load-bearing and gets a free pass — even if it's 40 turns old.

Entity facts are always carried forward in the rolling summary:
[Entities] files: file.py; functions: process_data(; tasks: #42

The model always has the facts it needs, even when 60% of the context has been compressed away.
